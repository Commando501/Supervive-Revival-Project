## 2d. Instrument bug found and fixed in `configs/fk24-stage.ps1`

The parked-state gate read `Read-Locked $capture 200000` — the **last 200 KB** of `capture.log`. But
the client fetches `/core-game/matches` **once, early**, so any later HTTP traffic pushes it out of
the window and the gate can never pass; the stager then burns its full 420 s `WaitParkedSec` and
aborts, wasting the launch.

MEASURED: attempt 1 passed **by luck** (fetch at offset 2,509,540 of 2,580,033 — 70 KB from the end);
attempt 2's identical fetch sat at 1,264,837 of 2,359,848 — **1.1 MB out of window** — and stalled.
FK-11's `[Core.Log]` verbosity work inflated per-run HTTP traffic enough to make the old window fail
routinely. Fixed to read the file whole (`capture.log` is recreated per `ags` start). After the fix the
gate passed in **0 s**. This bug was silently taxing every tutorial sitting.
