> **The disproof was accidental and decisive.** A leftover placeholder push sent the type

> with **no** error line. So `Type: %s` is emitted BEFORE the handler lookup. It proves the
> frame was received, envelope-stripped, converted to JSON and routed to the dispatcher. It
> proves **nothing** about a bound handler case.

> **WHAT THE SWEEP ACTUALLY ESTABLISHED (still real, still new):** all 33 types are received,

**S117, 2026-08-13 20:58-20:59 UTC. 33 frames, 2.5 s apart, one launch.**
First sweep ever run against a `/lobby` parser that could actually see our frames
(see `fk15-lobby-fragment-defect-20260813.md` — before the envelope fix, every frame
was buffered as a fragment and none was dispatched).

## No side effects, and that includes the ones expected to be destructive

The sweep was deliberately ordered benign-first, with `partyKickNotif`,
`partyLeaveNotif`, `userBannedNotification`, `userUnbannedNotification`,
`connectNotif` and `disconnectNotif` LAST, so that a session-ending handler could
not void the rest of the run. In the event **none of them did anything**:

- game alive, **0** crashpad handoffs
- both sockets held **581 s continuously** across the whole sweep — `disconnectNotif`
  did not close the socket, `partyKickNotif` did not alter the party
- no network activity of any kind

⚠ **A false positive I nearly recorded:** `LogNet:` and `7777` both read "0 -> 2"
after the sweep. Neither is a reaction. The two `LogNet:` lines are timestamped
**20:17:27 / 20:17:36** — startup map browses (`LVL_Login`, `LVL_LobbyV2`) that
predate the sweep by 40 minutes — and the two `7777` hits are our own dsNotif frame
echoed back in the log. The "0" baseline had been taken with a different pattern
earlier in the session. **Compare timestamps, not counts.**

## What this establishes, and what it does not

**ESTABLISHED:** routing is complete. All 33 types reach a bound case, parse, and
broadcast. The `/lobby` channel is fully functional in the receive direction for
the first time in this project's history.

**NOT ESTABLISHED:** that any handler *acts*. A `type:`-only frame carries no
payload, so a handler that deserializes into a struct and broadcasts a delegate has
nothing to act on — and may have nothing bound to it either. Zero
`Failed to Deserialize` means UE tolerated the missing fields, not that the fields
were unnecessary.

⇒ The open question is now **per-type payload**, not routing, and it is cheap: the
push console iterates a frame in seconds. Highest-value next targets:
`dsNotif` (DS connection info — the whole Path C premise), `partyGetInvitedNotif`
(a visible toast), `matchmakingNotif` (now re-testable — its 2026-06-29 nulls are
void, having never been dispatched).
