FOLLOW-UP OFFLINE RE: thunkExact bytes vs live (2026-09-02)
================================================================

Shim expectation
----------------
tools/sigbypass-mod/tutorial_launch.cpp:21224 (codex worktree):
    bool thunkExact = adjustThunk == g_modBase + 0x5516610;

The comment at :17261 documents this address as:
    //   AdjustHealth(float HealthDelta)  ULokiAbilitySystemComponent  [M] REAL 0x5516610

Live measurement (PID 41816, module base 0x7FF632800000)
--------------------------------------------------------
Reflected UFunction 'AdjustHealth' on class 0x15E4D1E0100 has:
  Func @+0xE0 = 0x7FF637A94270 = RVA 0x5294270

RVA 0x5294270 is DECRYPTED (COMMIT RX region 0xA000) — the exec-wrapper.
Prologue: 48 89 5C 24 08 57 48 83 EC 20 = classic MSVC / UHT execXxx thunk.

RVA 0x5516610 is UNDECRYPTED (COMMIT NOACCESS region 0x1000) — the impl.
0 bytes readable because nothing has ever executed there in this process.

Mechanism (proven by disassembling the exec wrapper)
----------------------------------------------------
The exec wrapper at 0x5294270 makes 4 calls, the LAST of which is:
    0x52942DF: call 0x5516610

That is EXACTLY the shim's expected address. So:
  - The shim's `thunkExact` check hard-codes the IMPL RVA (0x5516610).
  - The reflected UFunction.Func points to the EXEC WRAPPER (0x5294270).
  - The wrapper unpacks HealthDelta from FFrame.Locals, then calls the impl.
  - By UE's design, a reflected native function with parameters ALWAYS gets
    a UHT-generated exec wrapper; Func can never equal the impl address.

Consequence
-----------
`thunkExact` is a check that CANNOT PASS on this build (and probably on any
build with the same UE version). The comment "[M] REAL 0x5516610" appears to
have documented the impl address, but the shim's runtime check uses that
constant to compare against a value (Func) that has a different semantic.

Two fix paths
-------------
(A) REBUILD the S148 DLL with the check corrected to either:
    - Compare Func to the exec-wrapper RVA (0x5294270), OR
    - Read Func's own contents and find the tail `call <impl>` to derive the
      impl address dynamically (portable across builds), OR
    - Trust the reflection resolution and skip the byte-level check entirely.

(B) BYPASS AdjustHealth: externally poke Health.CurrentValue = 0x443B8000
    (750.0f) as a 4-byte write. Achieves the same end-state
    (Health drops by 250 from the seed we already poked). Loses the receipt
    "the game's own AdjustHealth function is callable" but proves the mover
    end-to-end via pure data pokes.

Path A requires shim source access; path B is one WriteProcessMemory in this
same live session.
