INTERPRETATION: this is not one bad instruction we can NOP. It is a cascade
from a missing / uninitialized render subsystem: the render graph runs with a
null or garbage resource, and WHERE it faults depends on timing/allocation
layout. Session 40's "guard the single TArray::Add at +0x2976FF0" plan would
patch one crash site and immediately hit the next.

WHY MIGHT RENDER STATE BE MISSING? (leads for Step 2, unconfirmed)
-----------------------------------------------------------------
1. ViewTarget suppression (STRONGEST lead, and cheap+safe to test):
   In session 41 we SUPPRESSED the server->client ClientSetViewTarget RPC to
   clear blocker A. That RPC tells the client PlayerController which actor to
   view (the camera/view target). A PlayerController with a null/absent view
   target can leave the scene renderer's view null -> FRDGBuilder::Execute
   dereferences a null view/scene and reads garbage at a small offset (0x28
   fits a view/scene member). We ASSUMED "the lobby drives its own camera" —
   that assumption is now suspect. TEST: instead of suppressing CSVT, inject
   its SUPERVIVE-modified signature the ServerVerifyViewTarget way (we already
   have that machinery — see supervive-rpc-signature-solved) so the client
   receives a valid view target. This is a NATIVE-STUB change: no injection, no
   anti-cheat exposure. Much cheaper/safer than a D3D12 injection patch.
   CAVEAT: the S40 full-suppression crash (no CSVT at all, different site)
   predates this suppression, so CSVT is not the sole cause — but it may be
   what shifted the S41 manifestation to a null-view read, and giving the client
   a real view target is a legitimate shot at unwedging it.
2. -nullrhi server <-> real-D3D12 client asymmetry: the server is headless, the
   client renders. A resource the client expects the server (or the normal
   client join flow) to have set up may be absent. Deeper RE.

NOT the anti-cheat fail-fast
----------------------------
Anti-cheat fail-fast signature is Rip=0xF0400001 / Rbp=0x537AC9E1 /
R11=0x95654773B3BC and only appears with a forbidden renderer flag/CVar. None of
these dumps match it; all crash inside SUPERVIVE's own RHI code with the real
D3D12 device + NVIDIA UMD loaded. We set NO renderer flags on the client.
