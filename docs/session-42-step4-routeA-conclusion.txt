ROUTE A FINDING 2 (the decisive one) — the mod-pak/AR route is LOGICALLY dead:
LokiAssetManager never consults the AssetRegistry for primary-asset enumeration.
------------------------------------------------------------------------------
Live log at the menu:
  LogAssetRegistry: Premade AssetRegistry loaded from '../../../Loki/AssetRegistry.bin'
  LogAssetRegistry: FAssetRegistry took 0.0008 seconds to start up
  LogAssetManager: Warning: Invalid Primary Asset Type :
      ChangeBundleStateForPrimaryAssets failed to find NameData
  LogAssetManager: Warning: Invalid Primary Asset Id :
      ChangeBundleStateForPrimaryAssets failed to find NameData
UAssetManager::ChangeBundleStateForPrimaryAssets looks up the MANAGER'S OWN type
registry (its NameData / PrimaryAssetTypeInfo map, populated by ScanPathsForPrimary
Assets / ScanPrimaryAssetTypesFromConfig), NOT the AssetRegistry. "failed to find
NameData" => that type map is empty for the requested types. LokiAssetManager
registers only from the content-service manifest (by ID) and SKIPS the config
directory scan, so the manager never enumerates the baked primary assets — and it
reads the AR only during a scan, which never runs.
=> Patching AssetRegistry.bin (the ENTIRE payload of the mod-pak route) cannot
   populate the grid, because the manager doesn't read the AR for enumeration.
   This is the trackb "kill criterion" — previously UNTESTABLE (deployment
   blocked) — now CONFIRMED from the live manager behavior.
