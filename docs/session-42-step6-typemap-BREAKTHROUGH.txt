WHAT THIS OVERTURNS

blocker.md and docs/hero-roster-attempts.md) was: "LokiAssetManager registers
primary assets ONLY from the content-service manifest and NEVER runs the config-
driven scan; the enumeration bypasses it; the manager never consults the AR." The
LIVE manager contradicts this: the 30 types ARE registered — which requires the
scan to have RUN (ScanPathsForPrimaryAssets reads the AssetRegistry per type). So:
  - The scan is NOT bypassed.
  - The manager DOES consult the AssetRegistry (registering a type scans AR paths).
  - => The trackb AR-patch "kill criterion" (manager doesn't consult AR) is likely
    FALSE. The AR-patch route may be VIABLE after all — IF the reason the grids are

    assets. Patching the AR so those directories resolve the baked primary assets
    could then populate the per-type lists.
