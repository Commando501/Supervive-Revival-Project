CHOSEN TRIGGER
--------------
UAssetManager::ScanPathsForPrimaryAssets(FPrimaryAssetType, const TArray<FString>&
Paths, UClass* BaseClass, bool bHasBlueprintClasses, bool bIsEditorOnly=false,
bool bForceSynchronousScan=true) -> int32.
Call it once per grid type on the game thread. Because the registry is full, each
call should find and register that type's assets. For Hero:
  Type       = FName "Hero"        (FName id 0x1A568 in this build's pool)
  Paths      = { "/Game/Loki/Characters/Heroes", "/Game/Skunkworks/Characters/Heroes" }
  BaseClass  = /Script/Loki.LokiHeroAsset  (find its UClass* at runtime via the pool)
  bHasBlueprintClasses = true, bIsEditorOnly = false, bForceSynchronousScan = true
(These paths/class were read live from the Hero FPrimaryAssetTypeData.Info — obj+0x10
= "/Script/Loki" + obj+0x18 = "LokiHeroAsset"; Info scan-paths array at obj+0x70.)
DO NOT target ScanPrimaryAssetTypesFromConfig — documented __report_gsfailure crasher
(CLAUDE.md), likely because SUPERVIVE modified a settings/state struct it reads.

X64 ABI for the call: rcx=this(manager), rdx=FName(8 bytes, {index,number}), r8=&Paths
(TArray<FString>*), r9=BaseClass(UClass*), [rsp+0x20]=bHasBlueprintClasses,
[rsp+0x28]=bIsEditorOnly, [rsp+0x30]=bForceSynchronousScan. Standard __fastcall,
no C++ exceptions (packer VEH kills them — keep payload no-throw).

DISASM PROBE RESULT (2026-07-02)
--------------------------------
Disassembled the ~11 Loki-override vtable slots (0x12Cxxxx / 0x12Dxxxx / 0x12C3xxx)
and filtered for a reference to the AssetTypeMap at this+0x478 (which ScanPaths must
touch to find/add the type). ZERO of them reference +0x478 in their entry region. =>

ScanPathsForPrimaryAssets is the STOCK impl in the engine .text (NOT the 0x12Cxxxx Loki
cluster) — it's a UNIQUE-but-base-impl vtable slot in an engine-code RVA band
(candidates seen in the vtdump: 0x11Exxxx, 0x135xxxx, 0x136xxxx, 0x34xxxxx).

RISK / OPEN QUESTIONS
---------------------
- The scan call may hit modified-struct issues like ScanPrimaryAssetTypesFromConfig
  did. ScanPathsForPrimaryAssets is a different fn but reads the same manager state;
  test on ONE type first.
- Constructing TArray<FString> in-payload is fiddly; prefer reusing an in-memory paths
  array. Confirm the Info scan-paths array (obj+0x70) is TArray<FString>.
- Must run on the game thread (asset manager is not thread-safe) — the mount_shim APC
  framework (tools/sigbypass-mod) already does game-thread dispatch.

WHY THIS IS THE RIGHT FIX (recap)
---------------------------------
The registry is full + correct (103,841 entries, heroes tagged). Deployment routes
(AR-patch, IoStore, pak-sign) are all aimed at the wrong layer. The only thing missing
is the manager running its own scan against data that's already present — a runtime
call, no data changes, no pak signing, no anti-cheat exposure (RPM/WPM + no-throw
injection are all proven safe in this build).
