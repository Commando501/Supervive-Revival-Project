-------------
Built tools/sigbypass-mod/scan_shim.cpp (no-throw DLL, adapted from mount_shim's
worker+game-thread-APC framework). It:
  1. finds the LokiAssetManager singleton (scan MEM_PRIVATE for the vtable
     RVA +0x888CB78, pick the instance whose AssetTypeMap (mgr+0x478) Num>0),
  2. queues an APC on the game thread (GGameThreadId slot RVA +0x9D49158),
  3. on the game thread, iterates the 30-entry AssetTypeMap and, per type, calls
     UAssetManager::ScanPathsForPrimaryAssets (RVA +0x34CF9F0) with args read
     straight from each type's Info block: Type FName @Info+0x00, BaseClass UClass*
     @Info+0x30, scan-paths TArray<FString> @Info+0x70; bHasBP=1,bEditorOnly=0,
     bForceSync=1.

manual-map, no UAC needed, no anti-cheat interaction. DllMain ran, worker found the

THIS CLOSES THE SESSION-42 DIAGNOSIS LOOP
-----------------------------------------
Root cause (proven): the in-game AssetRegistry was FULL (103,841 entries, heroes

ScanPathsForPrimaryAssets against the already-full registry populates them. Confirmed
end-to-end: 25 heroes registered, live, no crash.
