=========================== TL;DR ==========================================
The center "?" for OWNED heroes is NOT a bug in the owned-inventory change. It is "no selected
hunter": the party-slot / center preview actor renders the LOCAL PARTY MEMBER'S HeroAssetID, and
our synthesized solo party (interactive.buildSoloParty) sent NO hero on the member, so the member's
HeroAssetID was empty -> the actor showed BP_LokiHeroSelectPreview_UnknownHero (the "?").

FIX (this session, backend-only, no native patch):
  1. SEED: buildSoloParty's member now carries heroAssetId = the player's persisted selected hero,
     defaulting to "Hero:alchemist" (the inventory's IsDefault owned hunter). => on load the center
     renders that hunter instead of "?".
  2. PERSIST: a party member-update endpoint stores the picked hero and echoes it back, so a
     selection survives the ~1s /party poll (no revert) and a relaunch.

Both center visuals (main-menu slot 0 AND the WBP_UI_PartyHeroSelect preview) read the SAME party
member, so the single seed fixes both. Confirmed entirely from bytecode (below).

=========================== THE CENTER PREVIEW CHAIN (read from bytecode) =====
Two distinct widgets show the "you" hero; BOTH read the local party member's HeroAssetID:

A. MAIN-MENU CENTER SLOT (the visible "?" on the main menu):
   BP_MainMenuSpawner_MainMenu_PartySlot  (/Game/Loki/UI/MainMenu/)
     -> reacts to OnPartyUpdated / OnCosmeticUpdated
     -> Comp_MainMenu_PartySlotSubject (component): Determine Slot Party Model -> Get Members on Team
        -> DetermineCosmeticToShow -> **Resolve Cosmetics Bundle For Hero(member.HeroAssetID,
           member.CosmeticsAssetID)** -> OutCosmeticAsset + ShowUnknownForEmpty.
   Resolve Cosmetics Bundle For Hero (BPFL_Cosmetics) bytecode:
     [0] if IsValidPrimaryAssetId(InCosmeticAsset) -> OutCosmeticAsset = InCosmeticAsset
     [4] else if IsValidPrimaryAssetId(InHeroAsset) ->
     [6]   GetHeroAssetFromPrimaryAssetId(InHeroAsset) -> heroAsset
     [~]   **OutCosmeticAsset = heroAsset.DefaultCosmeticsBundle**   (derive the hero's DEFAULT skin)
     else -> empty -> ShowUnknownForEmpty = true -> BP_LokiHeroSelectPreview_UnknownHero ("?")
   => A VALID member.HeroAssetID with an EMPTY member.CosmeticsAssetID resolves to the hero's
      DefaultCosmeticsBundle -> a valid preview -> the real hero renders. So seeding heroAssetId
      ALONE is sufficient; no cosmetic id needed. Per-hero preview actors exist and are packaged
      (assetregistry namemap: BP_LokiHeroSelectPreview_Alchemist_Default, ..._Assault, etc.).

B. HUNTER-SELECT SCREEN PREVIEW (WBP_UI_PartyHeroSelect, when you open HUNTERS):
   ExecuteUbergraph_WBP_UI_PartyHeroSelect:
     GetPartyManager -> GetPartyModel -> **GetSelf** (the local PartyMemberModel = "me")
     -> BindDelegate(OnPartyHeroUpdated) to member.OnHeroAssetIDChanged
     -> RefreshContentPreview (reads the member's HeroAssetID -> HeroPicker.Update Hero Selection +
        ContentPreview_GotoScene to spawn the preview actor).
   Selecting an OWNED tile: OnHeroSelected -> TryPick -> **PartyManager.TryPickMyHeroAndCosmetics(
     HeroAssetId, CosmeticsAssetId, delegate)** (native). That sets the local member's HeroAssetID
     (fires OnHeroAssetIDChanged -> RefreshContentPreview) AND writes the member to the /party service.

WHY THE "?" PERSISTED (settled, do not re-derive): the roster tile's two exclusive gates are
  IsUseable(Selectable) = Entry.CanUse()  -> TRUE when OWNED
  IsPreviewable         = (NOT CanUse) AND (NOT IsDisabled) -> TRUE only when UNOWNED
Our owned-inventory change flipped all 25 to CanUse=true, which CORRECTLY disabled the unowned
purchase-preview. The center for OWNED heroes is the party-slot actor above, which needs a SELECTED
hero on the party member — which the stub never provided. Hence the "?".
