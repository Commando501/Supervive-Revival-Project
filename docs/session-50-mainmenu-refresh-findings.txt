=========================== THE GAME-THREAD BP-CALL TECHNIQUE (the reusable win) =============================
Problem: to run BP logic (Refresh) you must be on the game thread with the script stack; you can't just call the
impl. The pickup's plan was to hook ProcessEvent and ride an organic call — but ProcessEvent never fires here.
Solution that WORKS:
  * HOOK **ProcessInternal @ base+0x13454A0** (0x7FF683DC54A0) — prologue `48 89 5C 24 08` (mov [rsp+8],rbx), a
    clean 5-byte relocatable first instruction. This is "the shared BP VM entry every BP UFunction runs through"
    (confirmed: every BP UFunction's Func@+0xE0 == ProcessInternal; e.g. Refresh UFunc@+0xE0 = 0x7FF683DC54A0).
    It IS hot on the game thread whenever BP executes (18437 hits during one refresh cascade).
  * From the hook (game thread, guarded by g_inHook + GetCurrentThreadId()==GGameThreadId), CALL the real
    **ProcessEvent @ base+0x12C5A10** directly: processEvent(targetObj, UFunction*, params). ProcessEvent still
    works when called explicitly even though the game doesn't call it organically.
  * Inline 5-byte E9 hook + callable trampoline (stolen 5 bytes + jmp fn+5) + a HookStub that saves rcx/rdx/r8/r9,
    calls OnBP (C), restores, tail-jmps the trampoline. Alignment: entry rsp%16==8; push*4 -> %16==8; sub 0x28 ->
    %16==0 at the call; restored before tail jmp. Install per-trigger, uninstall on g_done (or 6s timeout) so the
    .text patch lives << the ~3-5min integrity wall. VEH crash logger captures any fault RVA. PROVEN no-crash.
  Tools/DLL: tools/sigbypass-mod/mainmenu_refresh_pi.cpp (the working PI variant). mainmenu_refresh.cpp is the
  same but hooks ProcessEvent (DEAD — kept for the record). mainmenu_refresh_test.cpp = single-shot ProcessEvent
  test (also 0 hits). Build: clang++ -shared -O2 <x>.cpp -o <x>.dll -lkernel32 from tools/sigbypass-mod.
