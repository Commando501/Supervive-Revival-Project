=========================== WHAT WAS PROVEN / DEAD ENDS (do NOT re-grind) ====================================
* The owned click does NOT reach the native pick (pick_probe hits=0, reliable). The selection is handled in
  NATIVE C++ (both HeroPickerSelectable BP classes have no click handler); it queries IsPreviewable/IsUseable.
* There is NO hero-pick REST route (full Theorycraft party route table dumped); hero is sent only as &hero= on
  /startSoloMode at QUEUE time. So a backend member-write route (S48 handleSetPartyMember) is a DEAD END.
* **The Func-swap technique (patch UFunction+0xE0) is DEAD** — proven with a valid control (ShouldHideHero
  across all variants stayed 0 while the roster demonstrably filtered). This build's VM runs a BP->BP callee's
  Script bytecode directly; Func is only used for native->BP. This is what silently defeated Route B twice.
  DO NOT use Func-swap for BP-invoked functions.
* **The Script-bytecode patch technique WORKS** (heap, no integrity wall — the VM runs Script directly).
  tools/re/script_patch.py: locate Script @UFunc+0x68, dump, jump0<off> (overwrite Script[0]=EX_Jump), pokebyte,
  restore. Proven: jumping ShouldHideHero->its Hide=true branch emptied the roster on filter.
* Writing member.HeroAssetID alone does NOT refresh the main-menu (tested: wrote Beebo, main menu stayed
  Mercury). Needs the delegate broadcast (hence Phase 3).
