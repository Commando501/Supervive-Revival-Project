THE REFLECTED ASSET API CANNOT REGISTER (sig_enum, LokiAssetManager — all native/reflected):
---------------------------------------------------------------------------------------------
  PrimaryAssetIDFromString(str) -> FPrimaryAssetId          [works]
  GetLokiDataAsset(FPrimaryAssetId) -> LokiDataAsset_Base*  [works; null for unregistered]
  AsyncLoadPrimaryAssets(WorldContext, TArray<FPrimaryAssetId> Assets, OnLoadComplete delegate) -> LoadAssetHandle*
  GetRestrictedAssetPath / GetReleaseAssetPath / GetReferenceAssetPath / GetDevelopmentAssetPath /
  GetDevelopersAssetPath -> FString  [config path getters]
There is NO reflected Scan/Register/AddDynamic UFunction. AsyncLoadPrimaryAssets can't help (it loads
already-REGISTERED ids). So registration must be done via a RAW native (not a UFunction) — the primitive's
UFunction-thunk mechanism doesn't reach it. (Confirms s52: "Scan/AddDynamic are native-only, not reflected".)

Goal: distinguish "missions registered but unloaded" (fix = AsyncLoadPrimaryAssets, easy) from "not
registered" (fix = raw ScanPathsForPrimaryAssets). Built probe10 = KismetSystemLibrary::
GetPrimaryAssetIdList(FPrimaryAssetType, OUT TArray<FPrimaryAssetId>) for Hero(control) + Mission.
RESULT: the game CRASHED during the query (marker reached [3], no [4]/[VEH]). The param mechanism is
NOT the cause (probe7/probe9 param calls are clean; probe10's thunk param-stepping is identical).

the documented intermittent menu crash coinciding). NOTE: several asset-manager / factory calls have now
crashed at the menu (probe6/8 factory, probe10 query) while GETTERS (GetMissionsModel, GetMissions,
GetLokiDataAsset, GetMissionModel) and PrimaryAssetIDFromString are all clean — the crashy ones are the
heavier registry/factory operations.
