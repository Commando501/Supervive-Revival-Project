ROOT CAUSE OF THE "10/20"
-------------------------
It's the DESIGN-TIME placeholder of ProgressTextv2 ("10/20") + ProgressBarv2 (Percent 0.5), left visible because
UpdateProgress never runs with real data. Live ground-truth (tools/re/live_bars.py, modal open): all 23 bars had
ObjectiveModel = NULL, total = the REAL per-mission max (already correctly bound from widget.Objective!), and
Percent = 0.500. The bind failed because our factory model (probe15/16) keyed MissionModel.Objectives by
ObjectiveProgress[i].ObjectiveName = None, so Map_Find(GetUniqueObjectiveName(...)) never matched -> ObjectiveModel
stayed null -> UpdateProgress didn't fire -> placeholder stayed.
(MissionObjectiveModel fields, dumped: Name(FName)@0x30, CurrentProgress(float)@0x38, Completed@0x60,
StartingProgress@0x64, Objective(->LokiMissionObjective)@0x78. The MAX is NOT here — it's widget.Objective.
TotalProgress from the DA struct. LokiMissionObjectiveData(48B): Prompt(Text)@0, TotalProgress(float)@0x10,
HideInMenus@0x14, ObjectiveClass(Class)@0x18. LokiDataAsset_Mission: Objectives(TArray)@0x88, XPReward@0x98,
InternalName@0x40. Class chain: DA_Mission_*_C -> LokiDataAsset_Mission -> LokiDataAsset_Base -> PrimaryDataAsset.
SuperStruct @+0x48.)

THE FIX (probe17, durable, native-only) — key the model's Objectives map by the REAL objective name
--------------------------------------------------------------------------------------------------
Extend the probe15 pipeline: after loading each mission DA, read DA.Objectives (@+0x88); for each
LokiMissionObjectiveData objective:
  key   = LokiAssetStatics::GetUniqueObjectiveName(objData)   // native, via the s55 primitive
  total = objData.TotalProgress (@+0x10)                      // informational; the bar reads the DA anyway
  build one FMissionObjectiveProgress { ObjectiveName=key, Progress=0, MaxProgress=total, StartingProgress=0 }
Put those in FMissionProgress.ObjectiveProgress (@+0x38) per mission, then
CreateMissionModelFromFinalProgress -> swap into ProgMgr.MissionsModel (@+0x3B8) as before.
Now the factory builds MissionModel.Objectives keyed by the real FName, with a MissionObjectiveModel whose
CurrentProgress=0. On (re)open, the widget's GetUniqueObjectiveName(same DA struct) matches the map key ->
Map_Find succeeds -> ObjectiveModel binds (CurrentProgress=0) -> UpdateProgress -> text "0 / TotalProgress",
Percent 0. Durable because the game's own BP does the binding every time the modal opens.

GetUniqueObjectiveName (LokiAssetStatics, NATIVE, thunk rva 0x52B3720): params [0] Objective(LokiMissionObjectiveData,
48B, CPF_OutParm|CPF_ConstParm @off0), [1] ReturnValue(FName @off48, Return). Call it with the s58 OUT-param recipe
(FOutParmRec for the Objective struct -> Locals+0); return FName in r8. Sample keys computed live: Tournament_WinGame
-> 'a2winarenagames' total=1; Tournament_Top3 -> 'BR_3Top4' total=3; Tournament_PlayAGame -> 'PlayAGame' total=5;
Tournament_KnocksAssists -> 'BR_Knocks_Assists' total=50.
