WHAT S63 SHIPPED (tools/sigbypass-mod/tutorial_launch.cpp — builds clean, both fixes live-verified)
---------------------------------------------------------------------------------------------------
Replaced the naked CustomLoginTramp with a plain C++ CustomLogin(gm,np,rr,portal,options,uid,err) at
GameMode vtable slot 285 (the Win64 ABI matches the vtable call site, so no naked asm needed). CustomLogin:
  PrepareLogin(gm)  ->  stock Login  ->  LogLoginResult  ->  RestoreLoginPatches  ->  return PC.
PrepareLogin runs INSIDE Login (game thread paused in our code — no sampling race), and does two things:
  (1) INSTRUMENT: diff the Loki PC C++ vtable vs stock APlayerController's, .text-guarded (rva 0x1000..
      0x7649000, break on 8 consecutive non-.text stock slots = past the vtable end), and flag override
      slots whose STOCK function references GameMode+0x3E0 (PlayerStateClass) = the InitPlayerState
      candidate(s). BP_LokiPlayerController_Dev_C's CDO is loaded only during travel, so this MUST run
      in-shim at Login-time (found via FindObjByName("Default__BP_LokiPlayerController_Dev_C"); its first
      qword = the C++ vtable; stock ref = "Default__PlayerController").
  (2) FIX (compile-time kFixMode):
      FIX_A2_STOCKPC     -> poke GM+0x3D8 (PlayerControllerClass) = stock APlayerController so
                            SpawnPlayerController makes a fully-stock PC (stock InitPlayerState creates the
                            PlayerState in standalone). Diagnostic; loses Loki PC input/camera/possession.
      FIX_TARGETED_INITPS -> de-override the InitPlayerState slot(s) in the Loki PC vtable to stock so the
                            Loki PC creates its OWN BP_LokiPlayerState locally, keeping full Loki behavior.
  All patches TRANSIENT: restored right after stock Login returns (integrity check covers .rdata vtables).
