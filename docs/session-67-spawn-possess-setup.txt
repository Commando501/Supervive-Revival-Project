★ BUG FIX 1 — the force-open "intermittent crash" was a LOGIN-HOLD TIMING bug (now reliable) ★
---------------------------------------------------------------------------------------------
Symptom: some force-open runs crashed with "Couldn't spawn player: ALokiGameMode::Login failed to Login" (the S61
login reject), not the expected pass. ROOT CAUSE: the slot-285 CustomLogin de-override is TRANSIENT (installed
before force-open, restored after a hold). The "open" console command is DEFERRED — the travel + Login run ~7s
LATER. The old code held ~8-12s via the sampling loop, which happened to cover Login. When I trimmed the hold, the
restore ran BEFORE Login fired -> the strict native Login ran -> fatal. FIX: hold CustomLogin installed until Login
actually fires — poll g_loginCalls (set by LogLoginResult), max 16s, then a grace, THEN restore. (See the
kPokeMatchModel==false branch in Worker.) Force-open now RELIABLY passes login + survives (LOGIN1 approved, tutorial
init -> Finished, game alive as spectator). The S63/S66 "intermittent" crashes were largely this.

★ BUG FIX 2 — SuperStruct offset was WRONG (0x40); it is @+0x48 this build (reusable correction) ★
-------------------------------------------------------------------------------------------------
Every class super-walk in the shim used UStruct::SuperStruct @ +0x40. DIAGNOSTIC (dump cls+0x38..0x50 as UObjects):
  cls+0x40 = 0xA (garbage);  cls+0x48 = BP_LokiPlayerController_C (the PARENT class);  cls+0x50 = first Child (UField).
So SuperStruct is @+0x48 (Children@0x50, ChildProperties@0x58 were already correct). The wrong 0x40 meant EVERY
super-walk silently traversed nothing — which is why (a) probes only ever showed a class's OWN funcs/props, (b)
PropOffset("PlayerState") returned 0xFFFFFFFF (PlayerState is on a super), (c) Possess wasn't found. FIXED all 6
super-walk sites (DumpClassFuncs, DumpParams, DumpFeatureToggles, DumpCoreGameState, PropOffset, the match-model
walk) 0x40 -> 0x48. After the fix the PC func dump correctly shows the full chain (BP_LokiPlayerController_C ->
LokiPlayerController -> PlayerController -> Controller).
