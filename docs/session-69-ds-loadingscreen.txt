>>> THE STALL (root cause) <<<
------------------------------
After TravelCompleted into LVL_Tutorial the client does NOTHING game-related and sits on the "DROP IN, GEAR UP…
LOADING" screen INDEFINITELY (verified stable 9+ minutes; only periodic Vivox/messenger/platform-refresh noise,
no crash, no timeout). CRITICALLY: there is NO "LogLokiGameState: Entering game state ..." after travel (there IS
one for the Login map: "Entering game state BP_LoginGameState_C"). The client has NO replicated GameState.

WHY: the stub's LokiNetDriver::IsClassNetCacheDivergent SUPPRESSES AGameStateBase (+ DefaultPawn + WorldSettings)
to keep the connection alive despite schema divergence. But the GameState is exactly the actor the client needs
replicated to leave the loading screen — its native match-state check (CurrentPhase / match-ready) never sees a
valid LokiGameState, so the loading screen never clears. This is the handoff's predicted "fundamental tension".

FIX DIRECTION (unchanged from handoff, now with the exact schema): un-suppress GameState + schema-inject a native
ALokiGameState mirror (LokiPlayerState_Missions pattern) so the client's replica hydrates with a PLAYING state.
