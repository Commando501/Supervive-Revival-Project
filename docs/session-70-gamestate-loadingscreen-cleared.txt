THE THREE BUGS FOUND + FIXED (all via the boot DumpClassNetCacheLayout + the crash asserts — headless, no guessing)
--------------------------------------------------------------------------------------------------------------------
1. GameStateBase 5-vs-4 rep misalignment (boot dump). Stock UE5.4 AGameStateBase replicates the DEPRECATED float
   ReplicatedWorldTimeSeconds AND the Double; SUPERVIVE replicates ONLY the Double (S69: 4 net props). The extra float
   at RepIndex 14 shifted EVERY LokiGameState RepIndex by 1. FIX: Loki.cpp StripReplicatedFlag(AGameStateBase,
   "ReplicatedWorldTimeSeconds") clears its CPF_Net before the ClassReps rebuild → GameStateBase yields 4 reps,
   LokiGameState starts at RepIndex 15 (boot-dump verified: matches the client).
2. bIsPushBased assert #1 (server crash on GameState replicate): "Assertion failed: bIsPushBased == Other.bIsPushBased
   [CoreNet.h:331]". FLifetimeProperty RepIndex collision — the stripped float kept a stale RepIndex colliding with the
   Double (different push settings). Parking its RepIndex at a sentinel + RemoveAll was NOT enough (below).
3. bIsPushBased assert #2 (ROOT). AGameStateBase::GetLifetimeReplicatedProps registers its props PUSH-BASED
   (DOREPLIFETIME_WITH_PARAMS_FAST); our runtime ClassReps rebuild (ForceSetUpReplicationData) + non-push DOREPLIFETIME
   props are inconsistent with push model → the assert. Disabling push model via net.IsPushModelEnabled=0 in
   DefaultEngine.ini [ConsoleVariables] did NOT take (log still: "PushModel HandleCreation is now enabled"). *** THE FIX
   THAT WORKED: *** ALokiGameState::GetLifetimeReplicatedProps DELIBERATELY does NOT call AGameStateBase's Super. It
   calls AActor::GetLifetimeReplicatedProps, then registers the 4 GameStateBase props BY NAME, NON-PUSH
   (AddGSBaseLifetimeProp: FindFProperty → OutLifetimeProps.Add(FLifetimeProperty(RepIndex))), then our 43 (non-push).
   All-non-push + float-free → the lifetime list is internally consistent → no assert. Push is a server dirty-tracking
   optimization only; the WIRE is identical. (The strip #1 is still required for ClassReps alignment.)

REUSABLE LESSONS (for the next mirror — pawn/PlayerState/etc.)
-------------------------------------------------------------
- To mirror an ENGINE-derived replicated class in this runtime-ClassReps-rebuild stub, do NOT call the engine base's
  GetLifetimeReplicatedProps (push-based FAST macros clash). Register the base's replicated props BY NAME, non-push,
  via FindFProperty + FLifetimeProperty(RepIndex), then your own via plain DOREPLIFETIME. Call AActor::Get... for the
  AActor tier.
- Watch for stock engine props the SUPERVIVE client DOESN'T replicate (deprecated float ReplicatedWorldTimeSeconds).
  StripReplicatedFlag(Class, "Prop") before the rep-data rebuild aligns the count. Verify with the boot
  DumpClassNetCacheLayout BEFORE launching a client — it caught the 5-vs-4 shift with zero wasted launches.
- net.IsPushModelEnabled=0 via ini [ConsoleVariables] did NOT disable push model here (still logged enabled). Don't
  rely on it; control the lifetime list directly instead.
