1. THE MECHANISM (fully reverse-engineered — this is why the loop happened)
--------------------------------------------------------------------------------
BattlepassInfoManager (BPIM) polls progressiontracks. Its RefreshOperation (a LokiOperation @BPIM+0x80)
re-arms FOREVER because adoption is version-gated and never succeeds:
  - Response body 0x57CFD90 fetches the endpoint; binds OnSuccess=0x57C8130 / OnError=0x57C7BD0.
  - OnSuccess (0x57C8130, __fastcall rcx=BPIM, rdx=&aggregate):
      cancel retry timer (0x57C1A00);
      `cmp [rdx+0x10](Version), [BPIM+0x50](adopted); jle skip`   <-- THE GATE
      copy aggregate.ProgressionTracks -> BPIM+0x40 (deep-copy 0x524D870);
      BPIM+0x50 = Version;  Broadcast BPIM+0x30 delegate (0x3071C30)  => ViewManager builds VMs;
      tail: if BPIM+0x50 < BPIM+0x58 (target, hardcoded =1 at factory 0x57BBFCE) -> re-arm (0x57D84F0).
  - The obfuscated SDK converter turns our parsed AccelByteModelsListProgressionTrackInfo (0x90) into
    the internal LokiPublishedProgressionTrack (0x120) and yields Version=0 (drops our tracks for a
    reason locked in VMProtect'd code — NOT statically isolatable; diag string "CurrentPublished
    ProgressionTracks has no Manifest" @0x8B40CE2). Version 0 !> adopted 0 -> broadcast skipped ->
    BPIM+0x40 stays empty -> adopted stays 0 < target 1 -> re-fetch forever.
  - CRITICAL: the UFunction SetCurrentPublishedProgressionTracks (thunk 0x5256880) is a COMPILED-OUT
    ret-0 no-op (impl 0xF7EC20 = `c2 00 00`, ICF-folded, 4659 callers). Do NOT try to call it.
  - BACKEND ROUTE IS EXHAUSTED: tried Active/window/enum, PrimaryAssetId-form ID, dropping
    RewardTrackCodes, ms-ISO dates — the oracle (BPIM+0x48) never went non-zero. No backend response
    satisfies the converter. Hence the shim.

2. THE FIX — battlepass_adopt_fix.cpp (tools/sigbypass-mod/)
--------------------------------------------------------------------------------
On the game thread (ProcessInternal hook base+0x13454A0), it:
  1. Finds BPIM, BattlepassViewManager, and Default__HuntersJourney_C (GUObjectArray class/name scan).
  2. Builds a LokiPublishedProgressionTracks aggregate = { ProgressionTracks:[ one
     LokiPublishedProgressionTrack: ProgressionTrackID FString "HuntersJourney",
     Details.InternalId FString "HuntersJourney", IsAccountPass=1, everything else zero/empty ],
     Version:100 }.
  3. Calls OnSuccess 0x57C8130(BPIM, &aggregate) directly -> Version 100 > adopted -> adopt +
     broadcast -> ViewManager builds the account VM.
  4. Directly writes AccountPassViewModel+0xE8 = &HuntersJourney_C (the build-time resolver keys off
     something other than ProgressionTrackID, so we bind it ourselves).
  (5. A populate call to 0x57DF4B0 is present but GATED OFF — it crashed; see §6.)
Marker: docs/battlepass-adopt-marker.txt.  FStrings are read-only (deep-copied by the game).

which enumerates ProgressionTrackAsset (+0xE8, now bound, 85 tiers) using the player's progress.

    cleared) need REAL content the zeroed versions don't provide; it derefs more context. (Reverted; gated off.)
