10. ★ FIELD 32 DIFF — IT IS CustomAnimationState (EnumProperty bit-width).
Computed from the stub boot dump (indices run cumulatively from the root: a level's own ClassReps
first, then its NetFields):
  Actor          FirstOwned=0  ClassReps=11 NetFields=0  base=0   -> idx 0..10
  Pawn           FirstOwned=11 ClassReps=14 NetFields=0  base=11  -> idx 11..13
  Character      FirstOwned=14 ClassReps=24 NetFields=7  base=14  -> props 14..23, RPCs 24..30
  LokiCharacter  FirstOwned=24 ClassReps=26 NetFields=14 base=31  -> props 31..32, RPCs 33..46
LokiCharacter owns 2 props, so ClassReps[24]=idx31=OutOfBoundsBufferTimeRemaining and
ClassReps[25]=**idx32=CustomAnimationState**. The class INDEX SPACE therefore lines up; what
disagrees is the WIRE WIDTH of that one field.
ROOT CAUSE: our mirror enum ELokiCustomAnimationStateMirror has ONE value (LCAS_None=0). UE
serialises an FEnumProperty with a bit-width derived from the enum's value count
(CeilLogTwo(NumValues)), so ours is NARROWER than the client's real CustomAnimationState enum ->
the reader desyncs at field 32. The LokiCharacterStub.h comment that the range was 'irrelevant
for Phase 1 because COND_SimulatedOnly means it is never sent to the owner' is WRONG on this
path: the failure is on the stub's RECEIVE side, so the owner-send condition does not protect it.
FIX (small, one enum): give ELokiCustomAnimationStateMirror the SAME NUMBER OF VALUES as the
client's enum so CeilLogTwo matches. GET THE COUNT LIVE — the client's LokiCharacter
CustomAnimationState FEnumProperty -> its UEnum -> NumEnums (the same reflection walk
rep_expand_class.py already does; S70 did exactly this for ERoundPhase/ELokiDayNightState and
noted 'matching value ranges keeps CeilLogTwo aligned'). Add that many dummy enumerators, rebuild,
rerun. If field 32 clears and a NEW index errors, iterate the same way (S54/S70 loop).
PRECEDENT: S70 hit and solved this exact class of bug on the GameState mirror's two enums.
